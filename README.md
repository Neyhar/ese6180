# Default observability-index sweep

`python run_experiment.py` now runs **20 distinct (dimension, observability-index) cases**, using feasible, deduplicated values from **h = 2, 4, 8, n**:

| Dimension n | Default indices h |
|---|---|
| 2 | 2 |
| 3 | 2, 3 |
| 4 | 2, 4 |
| 5 | 2, 4, 5 |
| 10 | 2, 4, 8, 10 |
| 50 | 2, 4, 8, 50 |
| 100 | 2, 4, 8, 100 |

Each case automatically tests context lengths **1, h−1, h, h+1**, removing nonpositive/duplicate values. Prediction horizons, execution lengths, and training seeds retain their previous defaults. This increases default runtime substantially relative to the old h=2-only sweep.

For the cyclic plant, sensors at coordinate indices 0,h,2h,... give exactly the requested index h. The runner verifies the resulting matrix observability index. Within a dimension, A, B, K, the independent random streams, the expert warm-up duration, and training boundary times are identical across h. Only C and the case's context lengths change. The shared warm-up is the largest required context minus one across that dimension's cases; large-h runs therefore also delay evaluation for the small-h comparison cases. Sensor number/layout and feature dimension change with h; this is not a pure change of history length alone.

Overrides:

```sh
# Restrict to selected exact indices (values above n are skipped).
python run_experiment.py --observability-indices 2 4 n
# Original fixed-context, h=2 suite:
python run_experiment.py --observability-indices 2 --contexts 1 2 4
# Force a fixed sensor count instead of sweeping requested indices:
python run_experiment.py --sensors 1
```

Explicit `--contexts` overrides automatic contexts; a request with no feasible index for any requested dimension is rejected. Index 1 is supported explicitly as a fully observed control case. With `--sensors`, the actual measured h determines automatic contexts.

Results default to `results/observability_sweep/`. Root-level CSV files combine all cases and include `observability_index`. Each case's model, config, time series, and plots live in `n<N>/h<H>/`, preventing collisions. `sweep_config.json` records the entire plan including resolved contexts and warm-up. `figures/observability_comparison.png` (also PDF) compares different h at r=h, when that context was requested. All per-case plots label h. Existing saved h=2 experiment results remain historical runs and are not regenerated by this change.

The expanded default was checked with 12 tests and a short integration sweep across all 20 cases. The short sweep validates execution and output organization, not long-run scientific conclusions.

# Matched one-step versus long-chunk experiments

The primary experiment now tests a genuine **one-step-trained, one-step-executed baseline** against chunk-trained policies. Both use exactly the same trajectory/time windows, features, ridge coefficient, and evaluation disturbances. The existing 2D demonstration is retained as `run_legacy_experiment.py` below.

## Run the new suite

Python 3.10+ with `python -m pip install -r requirements.txt`:

```sh
python -m unittest discover -s tests -v
python run_experiment.py
```

Default: dimensions **2, 3, 4, 5, 10, 50, 100**, contexts **chosen relative to h**, prediction horizons **200, 500, 1000**, execution lengths **1, 10, 50, 100, 200, 500, 1000** (only where execution <= prediction). Each episode has **5,000 scored actions after warm-up**; the last 1,000 define the late window. Three independent training/evaluation seeds are used with a fixed plant per dimension. Defaults include 32 training, 8 validation, and 8 evaluation trajectories per seed. All CLI values are adjustable; see `python run_experiment.py --help`.

Reproduce the completed initial sweep:

```sh
python run_experiment.py --observability-indices 2 --contexts 1 2 4 --steps 3000 --tail-steps 1000 --seeds 618 619 620 --train-trajectories 24 --eval-trajectories 4 --output results/dimension_sweep
```

The completed 10,000-step sweep is in `results/asymptotic_sweep` (3 seeds, 24 training and 4 evaluation trajectories per seed). Reproduce it with:

```sh
python run_experiment.py --observability-indices 2 --contexts 1 2 4 --steps 10000 --tail-steps 3000 --seeds 618 619 620 --train-trajectories 24 --eval-trajectories 4 --output results/asymptotic_sweep
```

For a longer investigation with the larger default dataset (10 full longest chunks):

```sh
python run_experiment.py --steps 10000 --tail-steps 3000 --output results/longer
python run_experiment.py --noise 0 --steps 10000 --tail-steps 3000 --output results/longer_noiseless
```

A small smoke run:

```sh
python run_experiment.py --dimensions 2 3 --horizons 20 --executions 1 5 20 --steps 100 --tail-steps 40 --seeds 618 --output results/smoke
```

## Exactly what is matched

`window_ids` selects identical (trajectory, boundary time) pairs across **all** contexts and prediction horizons, with enough future actions for the largest horizon and enough past observations for the largest context. The default uses up to 24 evenly spaced boundary times per training trajectory, over an early 128-step boundary interval. Trajectories extend far enough to supply every 1,000-action label. Keeping boundaries early avoids letting a mass of nearly zero terminal data dominate the fit.

The one-step policy solves ridge regression with only the current-action label. The chunk policy solves it with every future-action label. The same SVD of the feature matrix is reused for efficiency, but the one-step target is fit separately. Tests also compare against an independently augmented least-squares solve.

Because the objective separates across output columns, the fit for a shorter prediction horizon is **exactly a prefix** of the largest-horizon fit under matched windows. We exploit that identity instead of solving the same regressions repeatedly. Evaluation at the same execution length is also reused across prediction horizons, since the executed fitted rows are identical. CSV rows describe all requested horizons, but those reused rows are not independent evidence. The chunk execution-1 rollout is checked against the independently trained one-step rollout. Validation first-action MSE is reported separately; averaging an entire long chunk can dilute error with easy near-zero targets.

## The dimension-controlled model family

The new suite uses coupled cyclic linear systems, not copies of the original two-state example:

- `P` is a cyclic permutation matrix, `A = a P`, with default `a = 0.995` (slow decay).
- `B = b` is a seeded unit-norm vector: a single scalar action affects the state.
- `K = -0.05 b.T P`; hence `F = (a I - 0.05 b b.T) P` has norm at most `a < 1`.
- Sensors observe every other coordinate. The generator without an index argument has h=2; the primary runner now selects sensors for each requested h. Use `--observability-indices 2 --contexts 1 2 4` to recover the earlier fixed-threshold design.
- `--sensors 1` instead gives h=n for this family. Automatic contexts bracket this h; explicit `--contexts` is respected. Larger histories increase regression cost.
- `--system-seed` changes the input vector; `--seeds` changes datasets and evaluation draws, not the plant.

The same fixed plant per dimension is saved as `system_n*.npz`, with measured observability rank conditioning and stability radii in `systems.csv`. This is one structured family, not a claim about arbitrary n-dimensional systems. Scalar input with unit B also changes per-coordinate control authority as n grows; prefer **within-dimension baseline comparisons**, rather than interpreting cross-dimension error changes as a causal dimension effect.

Training is noiseless. Evaluation adds Gaussian process disturbances, default SD 0.02 per coordinate; observations are exact. Inputs include observed history and past applied actions. The expert controls max(context)-1 warm-up steps. All evaluation methods then use their own histories; scored errors exclude warm-up. Exact full-state expert trajectories with identical disturbances provide the reference.

## Outputs and interpretation

Every run saves:

- `metrics.csv`: one mean per dimension/seed/context/policy/prediction/execution configuration. Main metrics are whole-rollout, late-window, and cumulative squared tracking error, all normalized per state coordinate. `paired_tail_difference` subtracts the same episode's one-step baseline before averaging; negative favors chunking.
- `episodes.csv`: individual paired episode results, including failed-rollout indicators.
- `fit_diagnostics.csv`: rank, feature dimension, training-window count, and first-action weight discrepancy.
- `error_curves.npz`: full per-step errors averaged across episodes, separately for each training seed. Shorter-H duplicate curves are omitted.
- `figures/late_error_vs_execution.{png,pdf}`: chunk performance versus the one-step baseline, separate panel per dimension. Shading is the range of seed means, **not a confidence interval**. Divergent averages are flagged in the panel and retained in CSV.
- `figures/error_over_time.{png,pdf}`: block-mean errors reveal transients and later behavior.
- `figures/cumulative_error.{png,pdf}`: distinguishes persistent error from an early deviation that later decays away.

Default transient curves use context 2 and execution lengths 200/500/1000 alongside the baseline, chosen before seeing performance. Plot labels and panel dimensions are generated from configuration. Divergent trajectories (state/action norm above 1e6 or nonfinite values) retain infinite error and failure counts; they are never silently dropped. Finite graph axes cannot display infinity: inspect failure counts before interpreting a plot. A paired difference between two divergent cases is undefined (NaN), not evidence for either method.

**These are finite-horizon late-window measurements, not established asymptotic limits.** A 3,000-step run has only three complete 1,000-action chunks. Longer runs, additional seeds, and analysis of the augmented closed-loop transition matrix are needed for stronger stability or convergence claims. Small noiseless errors can be numerical/regularization artifacts; do not rank practically identical controllers by them.

# ESE 618: history, observability, and action chunking

Research question: how does context relative to the observability index affect closed-loop imitation error, and when does sufficient context favor shorter execution horizons?

This is an executable starting framework, not a claim that longer history always favors shorter chunks.

## Run

Use Python 3.10 or newer:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python run_legacy_experiment.py --output results/noiseless
python run_legacy_experiment.py --noise 0.02 --output results/disturbed
```

NumPy and Matplotlib are required. Each run exports a configuration JSON, a CSV of metrics, and PNG/PDF graphics in its figures/ subfolder. No neural-network packages or robot simulator are needed.

## Mathematical scope

Plant: x_(t+1) = A x_t + B u_t + w_t; observation y_t = C x_t. Expert: u*_t = K x_t. Training demonstrations are noiseless. Evaluation optionally includes process disturbances; observations remain noiseless. A and K in the example produce stable open-loop and expert closed-loop dynamics.

The expert is Markovian in the hidden state. Partial observability alone causes the learner's need for memory. Arbitrary expert memory, latent intent, nonlinear dynamics, sensor noise, and physical actuator delays are outside this initial model.

Context r counts observations including the current observation, and optionally r-1 past executed actions. Prediction H counts predicted actions. Execution ell counts actions used before replanning. They are independent parameters, with ell <= H.

For histories ordered oldest first:

- Y = O_r x_old + T_r U
- x_t = A^(r-1) x_old + R_r U
- M_r = [A^(r-1) O_r^dagger, R_r - A^(r-1) O_r^dagger T_r]
- x_t = M_r [Y; U], when O_r has full column rank and the history is noiseless.
- With F=A+BK, the exact H-action map stacks K F^j M_r for j=0,...,H-1.

`model.py` constructs these matrices explicitly. Reconstruction is tested on arbitrary inputs, not just expert trajectories. Unknown process disturbances invalidate exact finite-history reconstruction; the disturbed experiment intentionally measures this limitation.

## What is implemented

- `LinearSystem`: dynamics, observation, observability index, history matrices, reconstruction.
- `demonstrations`: full-state expert demonstrations; hidden states are used for evaluation, never as learned-policy features.
- `dataset` / `fit_policy`: ridge regression from histories to expert action chunks.
- `exact_policy`: model-aware oracle baseline using known A, B, C, K.
- `rollout`: chunk execution, observing at every step and replanning from the actual learner history.
- `run_legacy_experiment.py`: context {1,2,3,4}, execution {1,2,4,8}, fixed prediction horizon 8. Baselines include learned outputs-only, learned outputs-and-actions, and exact outputs-and-actions policies where observable.

The example hides the second state coordinate and has observability index 2. Edit `example_system()` to change the plant and expert; changing dimensions also requires updating the initial-state and disturbance shapes in the experiment runner.

## Evaluation conventions and interpretation

All methods receive the same three-step expert warm-up, initial conditions, and process disturbances. Warm-up actions are privileged initialization, excluded from scored action steps; deploying without an expert requires a separate initialization rule. The warm-up supplies enough history to every policy. Replanning observes the current state output before choosing the action. Measurements during a chunk are retained for the next replan.

Training and validation are separated by trajectory. Metrics include held-out chunk-action MSE, rollout expert-action MSE, state-trajectory error against a full-state expert receiving the same disturbances, and an illustrative quadratic state/action cost (Q=I, R=I; K is not claimed to be its optimizer). Standard deviations summarize evaluation episodes, not uncertainty across training seeds.

In the exact deterministic baseline, every execution length should match the expert to numerical precision. This is an essential control experiment. Do not infer an optimal execution length from tiny floating-point differences.

Expert trajectories can lie on a low-dimensional subspace of history features. The rank diagnostic exposes this: perfect training fit does not identify behavior on arbitrary learner histories. Ridge regression selects one extension, not necessarily the robust one. Past expert actions can reveal hidden state, which motivates the outputs-only ablation. More noiseless demonstrations of the same linear expert need not resolve this rank deficiency.

## Next research steps

1. Prove the exact history representation and the weaker action-reconstruction condition ker(O_r) subset ker(K A^(r-1)), with arbitrary known past inputs.
2. Sweep data count, ridge strength, and independent training seeds; inspect on-policy versus held-out error.
3. Add deliberately perturbed data collection with explicit expert labels if studying coverage beyond expert histories. Keep this intervention separate from ordinary behavioral cloning.
4. Add delayed-observation policies u_t = W_d y_(t-d), distinguishing delayed conditioning from actuator latency.
5. Compare systems with different observability indices and conditioning; define functional action recovery before claiming a universal context threshold.
6. Only then add sensor noise, model mismatch, or a robotics task.
